# 招生咨询会管理系统 & 招生组宣传活动管理系统 - 技术架构文档

## 一、总体架构

### 1.1 系统定位

| 模块 | 编号 | 定位 |
|------|------|------|
| 招生咨询会管理系统 | 6.1.2 | 全网聚合招生咨询会信息，智能筛选匹配，一键生成行程方案 |
| 招生组宣传活动管理系统 | 6.1.3 | 覆盖招生宣传全流程的一站式管理平台，实现招生工作数字化转型 |

### 1.2 技术栈

| 层次 | 技术选型 |
|------|----------|
| Web 框架 | FastAPI (async) |
| ORM | SQLAlchemy 2.0 (async, Mapped 声明式) |
| 数据库 | MySQL 8.0 |
| 缓存 | Redis |
| 数据迁移 | Alembic |
| 数据验证 | Pydantic v2 |
| 权限控制 | RBAC + 数据权限 |

### 1.3 架构分层

```
Controller (API路由层)
    ↓ 依赖注入 AuthSchema + AuthPermission
Service (业务逻辑层)
    ↓ 事务管理
CRUD (数据访问层)
    ↓ SQLAlchemy AsyncSession
Model (数据模型层) ← Schema (数据验证层)
```

### 2.1 咨询会信息聚合 (info_collection)

#### 2.1.1 功能点设计

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 后台全网抓取 | 定时任务抓取高招类咨询会信息，存入 consultation_info 表 | P1 |

#### 2.1.4 业务流程

```
第三方上传/手动录入
       ↓
  [pending 待审核]
       ↓
  管理员审核 ──→ rejected(退回修改)
       ↓ approve
  [approved 已审核] ──→ 触发合规诊断
       ↓                  (自动评分)
  信息可被筛选/报名
       ↓
  过期时间到达
       ↓
  [expired 已过期] → [archived 已归档]
```

#### 2.2.3 评分规则 (1.0版)

```
规则引擎: ComplianceScoringServiceV1

输入: consultation_info.organizer_nature
输出: compliance_diagnosis (score, level, risk_factors, suggestions)

评分表:
┌───────────────────────────────────────┬───────┬───────┐
│ 主办机构性质                            │ 分数区间 │ 等级  │
├───────────────────────────────────────┼───────┼───────┤
│ 单一省市区级官方机构                     │ 8-10   │ A     │
│ (电视台/电台/考试院/教育局)              │        │       │
├───────────────────────────────────────┼───────┼───────┤
│ 单一高中 / 单一高校                     │ 5-8    │ B     │
├───────────────────────────────────────┼───────┼───────┤
│ 多所高中联合(无第三方)                   │ 8-10   │ A     │
├───────────────────────────────────────┼───────┼───────┤
│ 多所高中联合(有第三方)                   │ 6-9    │ B     │
├───────────────────────────────────────┼───────┼───────┤
│ 多家第三方机构                          │ 3-6    │ C     │
├───────────────────────────────────────┼───────┼───────┤
│ 单一第三方机构                          │ 0-3    │ D     │
└───────────────────────────────────────┴───────┴───────┘

等级划分:
  A = 8-10分 (低风险，推荐参加)
  B = 5-8分  (中风险，谨慎参加)
  C = 3-6分  (较高风险，需评估)
  D = 0-3分  (高风险，不建议参加)

评分算法(1.0版):
  基础分 = score_min + (score_max - score_min) * 0.5
  若有官方机构参与 +1
  若有第三方参与 -1
  最终分 = clamp(基础分, score_min, score_max)
```

## 八、创新亮点技术实现

### 8.1 咨询会合规性诊断服务

**实现方式：** `ComplianceScoringServiceV1`

- 规则可配置，存储在 `compliance_rule` 表
- 评分引擎基于规则匹配 + 权重计算
- 1.0 版按主办机构性质评分，后续可扩展费用、规模、地点等维度
- 评分结果写入 `consultation_info.compliance_score` 和 `compliance_diagnosis` 表
- 支持批量诊断和单条诊断

### 8.2 智能行程规划

**实现方式：** `ItineraryService`

- 报名成功自动生成行程，避免手工录入
- 智能排期：检测时间冲突，基于地理位置优化路线
- 看板集成：行程状态与看板列自动同步
- 日历视图：按日期展示行程安排

### 8.3 自动去重合并同类活动

**实现方式：** `InfoCollectionService.deduplicate`

- 基于标题相似度(编辑距离) + 时间匹配 + 地点匹配
- 相似度阈值可配置(默认 0.8)
- 合并策略：保留信息最完整的记录，标记其他为 duplicate
- 支持手动合并和自动合并

### 8.4 AI微信排版

**实现方式：** `DocumentService.generate_wechat_content_service`

- 调用 AI 模块生成微信公众号格式内容
- 输入：活动文档内容 + 照片 + 关键词
- 输出：符合微信排版规范的 HTML 格式内容
- 支持重新生成和手动编辑
