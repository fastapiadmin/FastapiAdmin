# 左侧菜单精简设计

日期：2026-07-10
分支：`feat/single-tenant-slim`
关联：`2026-07-10-frontend-trim-design.md`、`2026-07-10-frontend-trim-round2-design.md`

## 目标

单公司内部控制面下,停用左侧栏里 SaaS/商业化/开发期/演示类菜单,只留内部真正需要的功能。

## 菜单机制(已探明)

- 侧栏 = 后端 `platform_menu` 表驱动。超管登录经 `user/service.py` 按 `status=0`(启用) + `client='pc'` 过滤后下发(`:176`,`:192`)。
- `status`:0=启用 1=停用。**置 1 即从侧栏消失且路由不注册**(最干净、可逆)。
- 种子 `backend/app/scripts/data/platform_menu.json`(无 id,按树结构)。导入脚本 `initialize.py` 对已有数据的表**跳过**(`if count.scalar(): return`)——所以改 JSON 只影响全新安装,改运行库才影响当前系统。二者独立,都要改。
- 5 个移动端菜单(首页/同事/打卡/消息/我的,`client='app'`)后端已过滤,PC 侧栏本就不显示,**不处理**。

## 用户确认

- **方式**:改运行库 `status=1` + 同步改种子 JSON(全新装一致)。不物理删除。
- **停用范围**(9 个根 + 全部后代,共 61 个节点):
  - 商业化 5 项(平台管理下):租户管理(15)、套餐管理(16)、订单管理(18)、发票管理(19)、租户工作台(20)
  - 工单管理(30,系统管理下)
  - 接口管理(4,整目录:Swagger/Redoc)
  - 代码管理(5,整目录:代码生成)
  - 案例管理(8,整目录:demo)
- **保留**:平台管理(菜单管理14/邮件管理17/插件市场21)、系统管理(除工单:字典/参数/部门/岗位/角色/用户/日志/公告)、监控管理(全)、AI管理(全)、任务管理(全)。

## 变更方式

### A. 运行库(当前系统立即生效)
一条幂等 SQL:把上述 61 个 id 的 `status` 置 1。用可回滚脚本(记录到 `backend/sql/` 或直接执行 + 文档留痕)。

### B. 种子 JSON(全新安装一致)
编辑 `platform_menu.json`,给对应 9 个根节点(及其 children 递归)加/改 `"status": 1`。因 JSON 无 id,按 route_path/title 定位这 9 棵子树,整棵置 status=1(含所有后代)。

## 验证

- SQL 执行后:`SELECT status,COUNT(*) FROM platform_menu GROUP BY status;` 应显示 61 行 status=1、158 行 status=0(219 总)。
- 重启后端 + 前端,超管登录:侧栏只剩 平台管理(菜单/邮件/插件市场)、系统管理(无工单)、监控管理、AI管理、任务管理。无 接口/代码/案例 目录,无 租户/套餐/订单/发票/租户工作台/工单。
- JSON 校验:`python3 -c "import json;json.load(open(...))"` 通过;停用子树的每个节点(含按钮)status=1。
- 回滚:反向 SQL(`status=0` where id in (...))即恢复。

## 不做

- 不物理删除菜单记录 / 不删组件文件。
- 不动保留菜单的权限、角色关联。
- 不动 client=app 的移动端菜单。
